## A0. 세 전제를 겹치면 나오는 불편한 사실

```
전부 홀드      →  순 노출 축소 없음
예비대 ≈ 0     →  신규 매수 자금 없음
한국장 위주    →  09:00–15:30 KST, 우주 작업 시간과 100% 겹침
```

이 셋을 동시에 놓으면 **지금 시스템은 구조적으로 아무것도 할 수 없다.**

| | 현재 상태 | 이유 |
|---|---|---|
| 상단 (매도) | **사정거리 밖** | 삼성 매도선 297,134 = 현재가에서 **+28.1%** 위 |
| 하단 (매수) | **탄약 없음** | 예비대 0 |

**증거는 오늘 자 `autopilot_state.json`에 있습니다:**

```json
"005930.KS": { "gap_mode":"DOWN", "gap_pending":true, "fills":0, "bot_fills":0 }
"000660.KS": { "gap_mode":"DOWN", "gap_pending":true, "fills":0, "bot_fills":0 }
```

**9개월 중 가장 큰 하락일(삼성 −9.0%, 하이닉스 −10.9%)에 봇의 체결은 0건이었습니다.**
갭 진입 플래그만 걸린 채 대기 중입니다. 전략이 나빠서가 아니라 **작동할 자원이 없어서** 멈춘 것입니다.

> 그러니 지금 필요한 건 새 전략이 아니라 **시스템을 다시 움직이게 만드는 최소 조작**입니다.

## A1. 밑장빼기는 "홀드"를 위반하지 않는다

가장 중요한 구분입니다.

```
손절      순 노출 ↓    수량 ↓    현금 ↑        ← 홀드 위반
밑장빼기   순 노출 =    수량 =    현금 =        ← 홀드와 양립  ✓
```

밑장빼기는 **매도-재매수 왕복**입니다. 33% 트림 3회를 돌려도 **삼성은 31주 그대로**입니다. 바뀌는 건 평단 하나뿐입니다.

| 삼성 (31주 유지) | 평단 | gap | 매도선(+6%) | 도달에 필요한 상승 |
|---|---:|---:|---:|---:|
| **현재** | 280,315 | 20.8% | 297,134 | **+28.1%** ← 사실상 불가 |
| 33% 트림 1회 | 258,239 | 11.3% | 273,733 | +18.0% |
| 33% 트림 3회 | 234,807 | **1.2%** | 248,895 | **+7.3%** ← 도달 가능 |
| 50% 트림 3회 | 224,754 | −3.1% | 238,239 | **+2.7%** |

| 하이닉스 (6주 유지) | 평단 | gap | 매도선(+7%) | 도달에 필요한 상승 |
|---|---:|---:|---:|---:|
| **현재** | 1,957,908 | 20.8% | 2,094,962 | **+29.2%** |
| 33% 트림 3회 | 1,652,565 | 1.9% | 1,768,245 | +9.1% |
| 50% 트림 3회 | 1,578,238 | −2.6% | 1,688,715 | **+4.2%** |

### 그래서 복구 경로는 하나뿐입니다

```
밑장빼기로 평단 하강
   ↓
매도 트리거가 사정거리로 진입   (+28% → +7%)
   ↓
매도 체결 → 현금 발생
   ↓
예비대 자연 복원 → 하단 매수 부활
   ↓
v^ 그리드가 양쪽으로 다시 작동
```

**홀드 전제에서 이것 말고 시스템을 재가동시키는 경로는 없습니다.** 순 노출을 줄이지 않겠다면, 평단을 내리는 것 외에 선택지가 없습니다.

### 정직한 대가

- **재매수 미체결 리스크**: −6% 지정가가 안 채워지고 급반등하면 그만큼 반등 미참여
- **회계상 실현손실**: 삼성 3회 −952,046 (경제적으로는 왕복 스프레드 +152,900/회 포착이지만 세금·수수료는 실제 비용)
- **KR 매도세** 0.15~0.18% × 매도 3회
- **하락 지속 시**: 3회로 부족 → 4·5회로 갈지, 멈출지를 **미리** 정해둬야 함 (본편 종료조건 (b))

> **가장 나쁜 시나리오는 1회 하고 무서워서 멈추는 것입니다.** 실현손실만 확정하고 평단 개선은 절반만 얻습니다. 어제가 정확히 그 패턴이었습니다 — 그래서 자동화가 필요합니다.

## A2. 하이닉스 입도 문제 — SKHY 스왑 (정리가 아니라 교환)

하이닉스 6주는 **트림 해상도가 너무 굵습니다.** 33% = 2주라 33.3% 단위로만 조절됩니다.

```
000660.KS  1주 = 1,621,000 KRW    →  6주 보유 시 16.7% 단위
SKHY ADR   1주 =   208,701 KRW    →  22주 보유 시  4.5% 단위
                                     해상도 7.8배 개선
```

**이건 "정리"가 아니라 "교환"이라 홀드 전제와 양립합니다.** 하이닉스 노출 총량은 그대로 두고, 들고 있는 그릇만 바꾸는 것입니다.

두 방향:

| | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | 000660.KS → SKHY로 이전 | 트림 해상도 7.8배, 미국장에서 무인 운용 가능 | 환전, 양도세 과세 체계 변경(해외주식 22%), 환율 리스크 |
| **B** | SKHY → 000660.KS로 이전 | 통화 단순화, 한국장 집중 전제와 부합 | 입도가 더 굵어짐 — **A1의 밑장빼기가 거의 불가능해짐** |

> 한국장 위주를 택하셨으므로 B가 자연스러워 보이지만, **B를 하면 A1의 복구 경로가 막힙니다.** 하이닉스만큼은 ADR 쪽에 두는 것이 기계적으로 유리합니다. 최소한 이중 보유 상태를 유지하더라도 **밑장빼기는 ADR 쪽에서만 실행**하는 절충이 가능합니다.

## A3. 한국장 × 우주 시간 — 무인화가 옵션이 아니라 전제

```
미국장 22:30–05:00 KST   →  자고 있어서 개입이 물리적으로 불가능했음
한국장 09:00–15:30 KST   →  깨어 있음. 유혹이 상시 존재.
```

미국장에서 손 체결 56%가 나왔다면, 한국장에서는 더 높아집니다. **따라서 개입 가능성 자체를 제거하는 환경 설계가 필요합니다.**

### 설계 원칙: 개입 인터페이스를 의도적으로 조악하게

지금은 앱에서 손쉽게 사고팔 수 있습니다. 그래서 5건이 손으로 나갔습니다.

```
현재:  세밀한 개입 가능 (아무 종목, 아무 수량, 아무 때나)
       → 반드시 쓰게 됨

목표:  개입 수단 = kill switch 하나
       "전부 정지" 만 가능. 부분 개입 불가.
       재개하려면 다음 결산 창(15:40)까지 기다려야 함.
```

부분 개입이 안 되면 "조금만 손보자"가 불가능해집니다. 정지하거나, 두거나 둘 중 하나입니다.

### 물리적 분리 체크리스트

```
□ 봇은 별도 가상데스크톱 / 별도 계정에서 실행
□ 우주 작업 화면에 트레이딩 창·차트 없음
□ 브로커 앱 푸시 전면 off (체결 알림 포함)
□ 봇 → 사람 알림 채널 완전 차단. 예외 없음.
   유일한 출력: 15:40 결산 브리핑 1개
□ 폰에서 브로커 앱 제거 또는 스크린타임 차단 (09:00–15:30)
```

### 하루 두 창 (한국장 기준)

```
창 1  08:50–09:00   장전 10분
      · gap 값 3개 확인 (삼성 / 하이닉스 / SKHY)
      · 오늘 밑장빼기 예정 여부만 확인 (승인 아님, 통보)
      · LIVE on → 화면 끔

창 2  15:40–15:50   결산 10분
      · 자동 브리핑 1장
      · 손으로 개입한 횟수 확인 (목표 0)
      · 룰이 없어서 즉흥 처리한 상황이 있었는지 1줄 메모 → 다음 룰 후보
```

**그 사이 6시간 30분은 경제가 존재하지 않습니다.**

## A4. 수정된 우선순위 — 4주 계획 (전제 반영)

본편 로드맵을 세 전제에 맞춰 재배열합니다.

```
0주차 (이번 주) ── 즉시, 코드 없이 ────────────────────────────
  □ 브로커 앱 푸시 전면 off
  □ 우주 작업 시간에 트레이딩 화면 물리적 분리
  □ 하루 두 창 시간 확정 (08:50 / 15:40) — 캘린더에 고정
  → 코드보다 이게 먼저다. 지금 상태로는 코드를 짜는 동안에도 주의력이 샌다.

1주차 ── 계측만, 매매 로직 무변경 ───────────────────────────
  □ gap = avg/price − 1 을 모든 카드에 크게 표시 (>8% 빨강)
  □ 매도선까지 필요 상승률 표시 ("+28.1% 필요" 같은 문구)
     → "지금 시스템이 사정거리 밖"이라는 사실이 화면에 보여야 한다
  □ asset_id 필드 (000660.KS ≡ SKHY)
  □ 전역 병력 회계 표시 (deployed / rescue / strategic)
  □ 주간 손 체결 비율 집계 (bot_fills vs fills)

2주차 ── 자동 밑장빼기 엔진 (이번 국면의 핵심) ─────────────────
  □ TRIM_PCT / REARM / max_rounds / 쿨다운 구현
  □ 로트 단위 추적 (LIFO — 지금은 평단만 있고 로트가 없음)
  □ FakeBroker 하네스에 밑장빼기 경로 추가 (기존 57 checks 확장)
  □ WATCH 모드 1주 관찰 → 트리거 로그가 납득되면 LIVE
  → 홀드 전제에서 시스템을 재가동시키는 유일한 수단이므로 최우선

3주차 ── 무인화 인프라 ────────────────────────────────────
  □ kill switch 외 개입 UI 제거
  □ 15:40 자동 브리핑 생성 (로그 → 1페이지)
  □ 봇 → 사람 알림 채널 전면 차단
  □ 종료 조건 (b)(c) 구현 — 밑장빼기 3회 실패 / 40거래일 시간종료

4주차 ── 예비대 복원 후 정상 체제 ──────────────────────────
  □ 슬롯/전선 체제 (예비대가 실제로 생긴 뒤에 의미가 생김)
  □ unit_cash 자동 유도
  □ 주간 부검 자동화 (D1/D2/D3)
```

**본편의 슬롯·전선 설계는 3주차 이후로 미룹니다.** 예비대가 0인 상태에서 슬롯을 나누는 건 의미가 없습니다. 먼저 시스템이 숨을 쉬게 만들어야 합니다.

## A6. 종결 기록 (2026-08-01)

**이 실행안은 채택되지 않았다.** 4주 계획 중 실행된 항목은 없다.

| 부록 A 항목 | 처리 |
|---|---|
| A1 밑장빼기 자동화 (TRIM_PCT / REARM / max_rounds / 쿨다운) | **미실행** — 매도–재매수 왕복은 봇에 넣지 않는다 |
| A2 하이닉스 ↔ SKHY 스왑 (입도 개선) | **미실행** — 포지션 교환 없음 |
| A3 무인화 인프라 (kill switch, 하루 두 창, 알림 전면 차단) | **미실행** — WATCH / LIVE 두 모드만, LIVE는 정규장 한정 |
| A4 4주 계획 전체 | **미실행** |
| 로트 단위(LIFO) 추적 | **미실행** — 브로커 평단 하나로 모든 선을 계산한다 |

### 대신 택한 길

밑장빼기는 **"내려간 평단을 사후에 끌어내리는 수술"** 이다. 롤백 체제는 그 수술이 필요해지는 상태에 덜 도달하도록 앞단을 고쳤다:

```text
① 기어가 캠페인 내내 고정      → CHASE가 평단을 구조적으로 따라간다
② 전량 EXIT 하나              → 잔여 포지션이 안 생긴다
③ 변동성→기어 컷포인트 상향    → 비싼 기어(G5, 주식 수 2배)가
   8/12/16/20 → 15/20/25/30      실수로 선택되지 않는다
```

배치 규모는 상한선이 아니라 ③에서 정해진다. 고정 상한은 두지 않았다 —
현금이 남아 있는데 사다리를 멈추는 쪽으로 틀리기 때문이다.

A0이 지적한 **"상단은 사정거리 밖, 하단은 탄약 없음"** 상태는 위 ①②③이 동시에 어긋났을 때 만들어진다. 봇에 후퇴 기동을 추가하는 대신, 그 조합이 잘 안 생기게 한 것이 이번 선택이다.

**손으로 하는 밑장빼기를 금지한 것은 아니다.** 지휘관의 재량으로 남기고, 봇의 룰에서 뺐을 뿐이다. 봇은 손매매를 감지하면 EXTERNAL / PARTIAL 로 기록하고 브로커 평단에서 두 선을 다시 계산한다 (기어박스 매뉴얼 §12).

**정직한 한계:** A0의 진단은 여전히 옳다. 예비대가 없으면 어떤 기어박스도 못 싸운다. 롤백 체제는 예비대를 *만들어 주지* 않는다 — 얕은 기어로 다 쓰는 속도를 늦출 뿐이다. 동시 전장 수 제한도, 캠페인 자본 상한도 코드에 없다 (매뉴얼 §8.3).
