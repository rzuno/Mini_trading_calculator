# Daily 443 V-Commandos Autopilot Manual v001

## 1. Purpose

Daily 443 V-Commandos is a short-cycle automated trading mode for highly volatile Korean stocks.

The purpose is not to predict the long-term direction of the stock. The purpose is to exploit repeated short rebounds inside a volatile chart.

Core idea:

```text
Enter after a daily pullback.
If the stock falls more, chase the average cost downward.
When the stock rebounds slightly, sell everything.
After selling, reset and prepare the next entry.
```

The strategy should usually finish within the same day, one or two days, or at most five trading days. If it remains trapped longer than that, the position is no longer in normal V-Commandos mode and should be treated as a recovery/manual case.

---

## 2. Relationship to Existing Strategy

This is a separate mode from the older 5D bait system.

### Old mode: 5D bait / manual calculator

Uses 5-day high, volatility gears, sell tiers, and wider swing logic.

Good for:

```text
manual trading
US stocks
sleeping computer
slower campaigns
bait-style trading
```

### New mode: Daily 443 V-Commandos Autopilot

Uses daily anchor, one load point, one chase point, and one exit point.

Good for:

```text
KR stocks
active Korean market hours
one or two selected stocks
high-volatility stocks
short-cycle automated trading
```

The new mode should not delete the old system. It should exist as a selectable strategy mode.

## 6. Vantage Point / Anchor Rule

The daily anchor is the reference point from which the LOAD price is calculated.

### First anchor of the day

At the beginning of each trading day:

```text
anchor = previous trading day close
```

Then:

```text
LOAD price = anchor × 0.96
```

### Intraday reset after full sell

If the bot sells the entire position during the same day:

```text
anchor = last sell price
```

Then the new LOAD price becomes:

```text
new LOAD price = last sell price × 0.96
```

This prevents the bot from selling and then immediately rebuying too high.

### Next day reset

At the next trading day:

```text
anchor = previous trading day close
```

The previous intraday sell anchor does not carry into the next day.

## 7. State Machine

The autopilot has five states.

```text
OFF
ARMED_EMPTY
DEPLOYED
TRAPPED
PAUSED
```

---

## 8. OFF State

Autopilot is disabled.

The program may still show calculated values, but it must not place, cancel, or modify orders.

Allowed behavior:

```text
show price
show anchor
show suggested LOAD
show suggested SELL/CHASE if manually entered
```

Forbidden behavior:

```text
no order placement
no automatic cancellation
no automatic modification
```

---

## 9. ARMED_EMPTY State

The stock is selected for autopilot, but there are no shares currently held.

Condition:

```text
shares == 0
autopilot enabled
```

The bot should maintain one BUY order:

```text
LOAD price = anchor × 0.96
LOAD quantity = 1 unit worth of shares
```

Only one LOAD order should exist.

If the LOAD order fills:

```text
state → DEPLOYED
avg_cost = actual average cost from Toss
shares = actual shares from Toss
chase_count += 0
```

Then the bot creates:

```text
SELL order at avg_cost × 1.03
CHASE order at avg_cost × 0.96
```

---

## 10. DEPLOYED State

The stock is currently held.

Condition:

```text
shares > 0
```

The bot should maintain exactly two intended orders:

```text
1. SELL order
2. CHASE BUY order
```

### SELL order

```text
sell_price = avg_cost × 1.03
sell_quantity = all shares
```

The SELL order is the exit door. It sells the entire position.

### CHASE BUY order

```text
chase_price = avg_cost × 0.96
chase_quantity = round(current_shares × 0.5)
```

If the CHASE order fills, the bot must update from Toss account data:

```text
new shares
new avg_cost
new cost basis
```

Then it must renew both orders:

```text
cancel/replace old SELL
cancel/replace old CHASE

new SELL = new avg_cost × 1.03
new CHASE = new avg_cost × 0.96
```

The bot must never assume the fill price. Toss account data is the source of truth.

---

## 11. Full Sell Handling

If the SELL order fills and shares become zero:

```text
state → ARMED_EMPTY
last_sell_price = actual sell fill price
anchor = last_sell_price
new LOAD price = anchor × 0.96
```

The bot may then place a new LOAD order from the last sell price.

This allows multiple same-day cycles:

```text
load
chase if needed
sell
reset anchor from sell price
load again if price drops enough
```

---

## 12. TRAPPED State

A position enters TRAPPED state when normal V-Commandos logic has failed to exit quickly.

Suggested trap conditions:

```text
holding_days > 5
or chase_count_today >= max_chase_per_day
or total deployed units in this stock >= max_stock_units
or reserve_units < reserve_safety_limit
or price falls too far without rebound
```

Initial conservative defaults:

```text
max_chase_per_day = 3
max_holding_days = 5
max_autopilot_stocks = 1 or 2
reserve safety threshold = 20%
```

In TRAPPED state:

```text
do not place new CHASE buys
do not place new LOAD buys
keep or revise SELL order
notify user
require manual decision
```

TRAPPED means:

```text
This is no longer daily commandos.
This is now recovery/manual mode.
```

---

## 13. PAUSED State

The bot must pause when it is uncertain.

Pause conditions:

```text
Toss account data unavailable
market data stale
order status unknown
API timeout after order request
unexpected manual/app order detected
more than one unmanaged order exists
position does not match local state
reserve safety violated
user presses kill switch
market closed or order not allowed
```

In PAUSED state:

```text
do not send new orders
do not repeat unknown orders
show reason for pause
wait for user confirmation or reconciliation
```

---

## 14. Polling Loop

The autopilot should poll Toss regularly.

Suggested interval:

```text
10–15 seconds
```

Each loop should do this:

```text
1. Fetch current price / quote
2. Fetch account holdings
3. Fetch open orders
4. Reconcile local state with Toss state
5. Detect fills
6. Decide desired orders
7. Cancel/replace only if necessary
8. Log the cycle
```

The bot should not blindly send orders every 10 seconds.

It should maintain the desired orders.


Forbidden:

```text

```

### DEPLOYED

Allowed orders:

```text

```

Forbidden:

```text

```

This mode is intentionally simpler than the old calculator.

---

## 16. Order Replacement Rule

Replace orders only when the desired order differs meaningfully from the existing order.

Examples:

```text
avg_cost changed after CHASE fill
shares changed
anchor changed after full sell
old order missing
old order wrong price
old order wrong quantity
```

Avoid unnecessary cancel/replace spam.


Local program state is only the strategy memory:

```text

```

If Toss and local state disagree, pause and reconcile.

```text

```

---

## 19. Tactical Interpretation

The tactic is not trying to buy the absolute bottom.

The tactic is trying to pull the average cost close enough to the current battlefield that a normal volatile bounce can extract the position.

Main sequence:

```text
LOAD at -4%
CHASE at -4% below average
SELL all at +3% above average
```

The motto:

```text
Stack lower, escape on the bounce, reset.
```

---

## 20. Why +3% Exit

The +3% exit is chosen because:

```text
+2% may be too small after fees, taxes, spread, and opportunity cost.
+4% may be profitable but can delay escape.
+3% is the first baseline for test-period automation.
```

Future candidates:

```text
442 = emergency extraction
443 = standard commandos
444 = patient high-volatility version
443H = +4% before chase, +3% after chase
```

For the first autopilot test:

```text
Use 443 only.
Do not mix multiple variants yet.
```

## 30. Final-Code Remarks (v001 addendum, 2026-07-09)

Program requirements decided for the first implementation.

### 30.1 Resting orders, one line per side

Toss DAY limit orders rest until filled or auto-cancelled at market close,
so the bot maintains desired orders instead of firing repeatedly.
Only one BUY line and one SELL line are ever intended (no ladders).

API constraint (verified live): a BUY and a SELL can never rest on the
same stock at the same time (opposite-pending-order-exists). Resolution:

```text
The SELL (exit door) is the resting order by default —
a brief bounce is caught at the exact touch.
The CHASE/LOAD buy is watched by the polling loop;
when price touches it: cancel SELL -> place BUY ->
after the fill, place the new SELL.
A placed BUY that does not fill stays resting;
the SELL side is then the watched one (symmetric).
The ~15s transition window is accepted risk.
```

### 30.2 Trimmed, conservative numbers

```text
Prices: snapped to the KR tick grid —
        BUY lines rounded DOWN, SELL lines rounded UP.
Chase quantity: max(1, floor(shares / 2))   (conservative half)
    1 -> buy 1 (total 2)     2 -> buy 1 (total 3)
    3 -> buy 1 (total 4)     4 -> buy 2 (total 6)
    6 -> buy 3 (total 9)     9 -> buy 4 (total 13)
Load quantity: floor(1 unit / load price), minimum 1 share.
```

### 30.3 Polling is per-stock, not global

The Save & Refresh full fetch and the autopilot poll are separate.
The poll (every ~15 s) touches ONLY the autopiloted ticker:
price, holdings(symbol), open orders(symbol), buying power.
The rest of the panel stays as of the last manual refresh.
The autopiloted card and its graph update live from the poll.

### 30.4 Stop rule (simplified from §12/§13)

The bot stops autopiloting a stock ONLY when the reserve cannot fund
the next buy (load or chase). It notifies (popup + red card banner +
log) and leaves the resting SELL in place. Other errors just log,
back off, and retry (order-hours-closed backs off ~5 minutes).

### 30.5 Interface

Enable/disable lives in the graph window (443 panel: ON/OFF, DRY RUN /
LIVE, state, anchor, LOAD/CHASE/SELL lines, status). While autopilot is
ON the manual Buy/Sell/Cancel graph buttons are disabled. The card
shows a 443 banner (DRY orange / LIVE red / STOPPED dark red).
Autopilot is always OFF at program start; enabling arms DRY RUN first,
going LIVE requires a confirm dialog listing the orders it will manage.

### 30.6 Limits

```text
Maximum autopiloted stocks: 2 (a third is blocked).
KR stocks first; US possible later (computer on overnight).
```

### 30.7 v002 refinements (2026-07-09, second pass)

Reload rule: after an intraday full sell, the new LOAD sits at
-3% of the sell price (not -4%), so a repeat dip re-enters near the
old cost (sell at 103 → reload near 100). At the next trading day the
anchor returns to the previous close and the -4% load applies again.

```text
anchor from prev close  → LOAD = anchor × 0.96
anchor from a sell      → LOAD = anchor × 0.97
```

Daily 443 live chart: a dedicated window ("Daily ▸" in the 443 panel
of the 5-day chart, active while autopilot is on). It shows the
intraday tick path inside the shaded 7% commando zone (chase/load
line → sell line), plus avg/anchor, today's campaign fill log
(what was bought at how much until all sold) and the deployed size.
It is the ONLY window that follows the 15-second ticks — the 5-day
chart and the main panel stay refresh-button-driven. While the path
stays inside the zone, the autopilot is working the plan.

Data problems: a failed poll (network, Toss outage, missing price)
skips the whole cycle — nothing is placed or cancelled on stale or
missing data — and retries in 15 s. After ~6 consecutive failures
(~90 s) a one-time warning popup announces the outage; the bot stays
enabled, idles, and recovers by itself. Resting orders stay on Toss
(DAY orders die at market close anyway).

Reserve gate: UNLOCKED for the test phase (RESERVE_GATE=False in
core/autopilot.py) while the KB proceeds have not landed. Dry-run
keeps trading on paper regardless of reserve; live mode relies on
Toss rejecting unaffordable buys (that broker rejection still stops
the bot with the popup). Flip RESERVE_GATE=True to restore the
self-stop once real cash is back.

### 30.8 v003 — the WATCHER model (2026-07-10)

The autopilot pre-places NOTHING. It watches the price every 10 s and
fires a real LIMIT order only at the moment a line is crossed:

```text
EMPTY:     price <= LOAD  -> BUY one unit
DEPLOYED:  price <= CHASE -> BUY the chase quantity
           price >= SELL  -> SELL everything
```

While our just-fired order rests unfilled, the watcher waits (no
duplicate requests). If the opposite line triggers first, our unfilled
order is cancelled and the new side fires (exit has priority). Orders
placed manually in the app/web are NEVER cancelled — external fills
flow back through the account data and the lines reset, so app and API
trading coexist without friction and without end-of-day cancel noise.

Modes (buttons live in the Daily 443 window, top right):

```text
WATCH — bare live info: zone chart + lines, no orders at all.
        Opening the window arms it; closing the window stops it.
DRY   — paper simulation (virtual fills, not connected to reality).
LIVE  — the real watcher. Allowed ONLY during regular market hours
        (KR 09:00-15:30 KST; US 09:30-16:00 ET, DST-aware).
        Pre/after market: only WATCH and DRY.
        When the session ends, LIVE drops back to WATCH by itself.
```

The card grew a big 443 button (right of the sell gear): its color IS
the status — grey OFF, blue WATCH, orange DRY, red LIVE, dark-red
STOP. Clicking it opens the Daily 443 window. The 5-day graph is back
to the pure 5D bait system (no autopilot overlay); the bait-hit title
tag is gone too (trigger state shows as ladder-number colors only).

The campaign fill log is campaign-scoped: it records every buy
(date/time, quantity, actual price backed out of the broker avg) from
the LOAD on, seeds a HOLD line when armed onto an existing position,
survives day rollovers, and is cleared the moment the position is
fully sold. External (app/web) fills appear in it too while the
watcher is on.

No cap on watched stocks anymore (§18's max-2 is retired) — selection
is the user's self-rule; empty cards now sort by 5-day volatility to
make that choice easy. Poll = 10 s.

### 30.9 Pedals

```text
443 (default):  LOAD -4%   CHASE -4%   SELL +3%   reload -3%
                chase size = floor(n/2)   (1,1,1,2,2,3,3,4...)
352 (safe):     LOAD -3%   CHASE -5%   SELL +2%   reload -2%
                chase size = ceil(n/2) — aggressive: 9->5, 13->7
```

Same ~7% zone, selectable per stock in the Daily 443 window. In the
watcher model a pedal change cancels nothing — the lines just move.
